# 3. اما یک باگ جدی پیدا کردم: Thread Safety

این تست را انجام دادم:

```text
4 threads
40 simultaneous cycles
```

نتیجه:

```text
40 requests
0 Python exceptions
39 cycles دارای error
39 cycles غیر-completed
```

خطاها:

```text
Illegal transition START_CYCLE from state READING
Illegal transition START_CYCLE from state CONTEXTING
...
```

یعنی این:

```python
orchestrator.run_cycle()
```

برای **چند Thread همزمان روی یک Orchestrator** امن نیست.

State machine یک state مشترک دارد:

```text
IDLE
READING
CONTEXTING
A1
A2
A3
...
```

Thread A می‌رود:

```text
IDLE → READING
```

Thread B همزمان می‌آید و می‌گوید:

```text
START_CYCLE
```

ولی سیستم دیگر `IDLE` نیست.

### شدت

**HIGH**

چون اگر کسی مستقیماً یک Orchestrator را از چند worker همزمان صدا بزند، چرخه‌ها خراب می‌شوند.

### نکته مهم

Web Control Plane این مشکل را فعلاً با:

```python
with self.lock:
```

دور زده و تست API هم این را تأیید کرد:

```text
20 concurrent API requests
20/20 = HTTP 200
0 cycle errors
```

پس:

```text
Web → ControlPlane → lock → Orchestrator
```

فعلاً سالم است.

ولی:

```text
Multiple threads → same Orchestrator
```

سالم نیست.

# 4. یک باگ دوم: CLI Kill Switch

این را واقعاً اجرا کردم:

```bash
python -m trader.cli kill-switch on --reason stress
```

و شکست خورد:

```text
AttributeError:
'Namespace' object has no attribute 'symbol'
```

مشکل در `_build_orchestrator()` است:

```python
if args.symbol:
```

ولی parser مربوط به:

```text
kill-switch
```

اصلاً `symbol` ندارد.

حتی یک مشکل معماری دیگر هم دارد:

```bash
kill-switch on
```

یک Orchestrator جدید می‌سازد، Kill Switch را فعال می‌کند و process تمام می‌شود.

بعد:

```bash
kill-switch off
```

یک Orchestrator جدید می‌سازد.

بنابراین **Kill Switch فعلی CLI persistence واقعی بین processها ندارد**.

در مقابل، Kill Switch داخل همان Orchestrator درست کار کرد:

```text
activate
→ HALTED
→ run_cycle = halted_at_start
→ resume
→ IDLE
→ cycle works
```

پس مشکل خود مکانیزم Kill Switch نیست؛ **CLI lifecycle/persistence** مشکل دارد.
